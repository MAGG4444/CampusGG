# Forum feed ranking

For You uses the current authenticated account's followed channel IDs and the catalog's aliases. Let `age` be days since publication, `L` the real like count and `C` the real reply count. Its descending score is `ln(1 + 0.05 * min(L, 20) + 0.1 * min(C, 10) + followed) - age / 7`, where `followed` is 1 for a recognized followed channel and 0 otherwise. This is the logarithm of an exponentially decaying, bounded engagement-and-follow weight. All posts remain eligible, including unassigned historical posts.

Popular and channel Hot use `ln(1 + min(L, 100) + 2 * min(C, 100)) - age / 3`. Top uses `L + 2 * C` with optional rolling 1-day, 7-day, 30-day or all-time post-creation windows. New sorts by creation time. Ranked ties use creation time and post ID descending; New uses the same two fields. Popular includes recognized channel posts only. Channel feeds resolve historical game aliases from the catalog. Following remains a separate newest-first feed.

SQL aggregates likes and comments per eligible post rather than issuing requests per post. Ranking still requires database work across eligible posts and may need materialized aggregates as the dataset grows. The ranking index migration adds `(created_at DESC, id DESC)` on forum posts and `post_id` on comments. Existing like uniqueness starts with `post_id`. Pagination uses offsets; concurrent changes and rolling time-window boundaries can move results between requests. The log-space age term subtracts the same current-time constant for every post, so time alone does not reorder unchanged results within a fixed candidate set.

The public incremental feed is `GET /forum/feed/all` with `search`, `sort=new|liked|replies`, `page`, and `limit`. Search is case-insensitive and matches title, body, game, username, or display name before pagination. The response retains `{ posts, total, page, limit }` and includes aggregated like and reply counts. The existing `/forum/posts` endpoint remains unchanged. Newest-first queries aggregate counts for the selected page; engagement-based ordering must aggregate counts across the eligible result set.
